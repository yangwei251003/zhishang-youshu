## 1. 首页留白：现状与根因

### 1.1 实测数据（1600×900，首次进入、引导弹层关闭后）

| 栏 | 栏高 | 内容实际结束位置 | 底部空白 |
|---|---|---|---|
| 左栏 `.left-rail` | 1694 | 1694 | **0** |
| 中栏 `.canvas-workspace` | 1694 | 1003 | **690** |
| 右栏 `.right-rail` | 1694 | 1218 | 476 |

`.workbench-body` 高 1694px（其父 `.workbench` 1834px），页面 `scrollHeight` 2196px。

中栏构成：`workspace-top` 62 + `dual-canvas` 753 + `history-section` 188 = **1003px**。

### 1.2 根因：驱动整行高度的是**左栏**，不是右栏

`.workbench-body` 是 `display:grid`，未设置 `align-items`，默认为 `stretch`——三栏被强制拉伸到**同一行高 = 最高栏的自然高度**。

左栏内容明细（实测）：

| 左栏子项 | 高度 |
|---|---|
| `.apprentice-tasks`（V3 新增·七任务新手面板） | **564** |
| `.mode-switch` | 50 |
| `.lessons-section`（实验章节：3 单元 + 迁移题） | **543** |
| `.rail-section`（折叠方式） | 161 |
| `.rail-section.tools-section`（剪切工具） | 247 |
| `.rail-help`（底部入口） | 51 |

`564 + 543 = 1107px` 两项就占了左栏 65%。左栏自然高度 1694px 因此成为整行高度，中栏只有 1003px 内容，多出的 **690px 就是用户看到的那片留白**。

> 修正上一版判断：早期抽样曾把右栏（含 553px 实剪视频卡）当成长高元凶，复测后确认**右栏自身也只用到 1218px、同样留白 476px**。这不是"某一栏太高"，而是**三栏内容量差异大 + 强制等高**的结构问题。任何只改右栏的方案都不会解决它。

### 1.3 为什么不能简单地改成不等高

最直觉的做法是 `.workbench-body { align-items: start }`。**不采用**，原因：

- 三栏背景色各不相同（左 `#f9f3e8`、右 `var(--paper)`、中透明），不等高后三栏底边参差，卡片内会露出三条高低不同的断口，观感比留白更差；
- 栏间分隔线（`border-right` / `border-left`）会随栏高截断，破坏"一张工作台"的整体感；
- 移动端（≤1050px）已把右栏改成跨列网格，`align-items` 改动会连带影响两套布局。

**因此策略是：保留 `stretch`，改成"让最短的栏有内容可填、让最长的栏不再那么长"。**

## 2. 首页留白：修复方案（按优先级）

目标：**四档断点（1280 / 1440 / 1600 / 1920）下，三栏中任意一栏的底部连续空白 ≤ 160px。**

### L1（P0）左栏瘦身 —— 这是主要工程量所在，预计削减 ≈ 740px

**L1-a 新手任务面板 `.apprentice-tasks`：564px → ≈ 64px**

面板已在 `App.tsx` 中以 `collapsedInitially={returningDevice}` 支持折叠，但**首次访问（新用户）默认展开**，于是首屏就顶上去 564px。改为：

- 保留 V3"一打开就出现"的要求，但**折叠态也能看到进度**：折叠时显示一行 `纸上第一课 · 已完成 2/7` + 进度条 + 展开箭头；
- 首次进入时**展开**（不违背 V3 需求），但用户点过第 1 个任务后即自动收起；
- 展开内容改为 `max-height: 320px; overflow-y: auto`，避免 7 个任务全部撑开。

**L1-b 实验章节 `.lessons-section`：543px → ≈ 300px**

- 该 `<details>` 目前 `open={!narrow}`，即**桌面上强制展开**。改为桌面也**默认收起**，`summary` 文案改为 `实验章节 · 当前：<当前课名>`（保持可发现性）；
- 若产品上不愿收起，退一步：`.lessons-section { max-height: 300px; overflow-y: auto; }`，并给滚动区加 `scrollbar-width: thin`（与既有 `.history-track` 一致）。

两项合计削减约 **740px**，左栏落到 ≈ 954px，此时**左栏反而成为最短栏**。

### L2（P0）中栏弹性填充 —— 承接残余空白

`.dual-canvas` 在 `styles.css:605` 被设为 `flex: 0 0 auto`，`.history-section` 在 `styles.css:606` 被设为 `margin-top: 0`——这两条是上一轮"让历史紧贴操作区"的改动（源码注释：`Screenshot follow-up: keep history next to the action`），也正是**当前中栏把余量全部堆到最底部**的直接原因。

改法（**不要简单回退**，回退会把空白挪到画布与历史之间）：

```css
/* 中栏：在画布与历史之间插入可伸缩的"纸纹过渡带"，把余量吸收到有设计的位置 */
.workspace-filler {
  flex: 1 1 auto;
  min-height: 20px;
  display: flex;
  align-items: center;
  justify-content: center;
  background-image: url('/v2/paper-grain.svg');
  background-repeat: repeat-x;
  background-position: center;
  opacity: .45;
}
.workspace-filler::before {
  content: '纸 上 有 数';
  font-family: var(--serif);
  font-size: 12px;
  letter-spacing: 10px;
  color: var(--zs-text-muted, #9b8e7e);
}
```

在 `App.tsx` 中栏 `.dual-canvas` 与 `.history-section` 之间插入 `<div className="workspace-filler" aria-hidden="true"/>`（纯装饰，不进无障碍树）。

- 余量小时它只有 20px，几乎不可见；
- 余量大时它撑满，把"死白"变成一条带纸纹与字样的过渡带，**空白读起来是设计留白而不是排版事故**；
- `aria-hidden` + 纯 CSS 背景，不影响打印（打印样式已隐藏装饰，见 `@media print`）。

### L3（P0）右栏收敛

| 项 | 现状 | 改法 |
|---|---|---|
| 实剪视频卡 `.real-cut-video.real-cut-compact` | 364px，默认展开 | 默认**折叠为一条 56px 摘要行**（封面缩略 + 标题 + 时长 + 播放按钮），点击后在原位展开播放器。削减 ≈ 300px |

### L4（P1）兜底：内容再平衡

若 L1–L3 完成后某档断点仍 >160px，按此顺序追加（不要一次全上，逐项验证）：

### 验收脚本（建议 codex 落地为 `scripts/check-layout.mjs`）

```js
// 逐断点断言：三栏底部空白 ≤ 160px，且无横向溢出
for (const [w, h] of [[1280,900],[1440,900],[1600,900],[1920,1080]]) {
  const page = await browser.newPage({ viewport: { width: w, height: h } });
  await page.goto(BASE_URL, { waitUntil: 'networkidle' });
  await dismissOnboarding(page);               // 关闭首屏引导弹层
  const r = await page.evaluate(() => {
    const body = document.querySelector('.workbench-body').getBoundingClientRect();
    const blank = (sel) => {
      const c = document.querySelector(sel);
      const maxB = Math.max(...[...c.children].map(e => e.getBoundingClientRect().bottom));
      return Math.round(body.bottom - maxB);
    };
    return {
      left: blank('.left-rail'), mid: blank('.canvas-workspace'), right: blank('.right-rail'),
      overflowX: document.documentElement.scrollWidth - document.documentElement.clientWidth,
    };
  });
  assert(r.left <= 160 && r.mid <= 160 && r.right <= 160 && r.overflowX <= 0, `${w}×${h} ${JSON.stringify(r)}`);
}
```

## 3. 顶部导航激活态：现状与修复

### 3.1 根因：激活态是**写死的字符串**，不是状态

`src/App.tsx:473`：

```tsx
<nav className="main-nav" aria-label="主导航">
  <button className="nav-active" onClick={...}>实验工坊<span className="nav-dot"/></button>
  <button onClick={() => { setInspiration(true); setModal(null); }}>剪纸灵感库</button>
  <button onClick={() => setModal('manual')}>学习手册</button>
  <button onClick={openWorks}>我的作品</button>
  <button onClick={() => openApprentice(...)} disabled={!hydrated}>纸上第一课</button>
  <button data-tour-entry onClick={() => startTour()} disabled={!hydrated}>使用引导</button>
</nav>
```

- `className="nav-active"` 与 `<span className="nav-dot"/>` **只出现在第一个按钮上**；
- 其余 5 个按钮**没有任何 className、没有 `aria-current`**；
- 页面状态（`inspiration` / `modal`）与导航**完全解耦**。

本次复现证据：点击「剪纸灵感库」后 `.inspiration-library` 已渲染（高 5210px）、`main[hidden]=true`，但导航快照仍是 `实验工坊 → cls:"nav-active", hasDot:true`，`剪纸灵感库 → cls:"(none)"`。打开「我的作品」弹窗（标题「我的纸上实验」）时同样无任何变化。

### 3.2 修复：单一数据源 + 派生激活态

**关键区分：这 6 项不是同一类东西。**

| 导航项 | 类型 | 激活态语义 |
|---|---|---|
| 实验工坊 | 页面（主视图） | 当前为工坊视图时激活，`aria-current="page"` |
| 剪纸灵感库 | 页面（`inspiration === true`） | 当前为灵感库时激活，`aria-current="page"` |
| 学习手册 | 弹层 | **不常驻高亮**；打开时 `aria-expanded="true"` + 临时高亮 |
| 我的作品 | 弹层 | 同上 |
| 纸上第一课 | 弹层／任务 | 同上 |
| 使用引导 | 动作 | 打开时高亮 |

只有**页面型**项获得常驻激活态（因为用户需要知道"我在哪一页"）；弹层型项打开时高亮、关闭即恢复——若让弹层项也常驻高亮，会出现"灵感库 + 学习手册同时标红"的矛盾状态。

推荐实现骨架：

```tsx
type NavItem = {
  id: string;
  label: string;
  kind: 'page' | 'overlay';
  isActive: () => boolean;
  onSelect: () => void;
  disabled?: boolean;
  tour?: boolean;
};

const navItems: NavItem[] = [
  { id: 'workshop',    label: '实验工坊',   kind: 'page',    isActive: () => !inspiration, onSelect: () => { setInspiration(false); setModal(null); document.getElementById('workshop')?.scrollIntoView({ behavior:'smooth' }); } },
  { id: 'inspiration', label: '剪纸灵感库', kind: 'page',    isActive: () => inspiration,  onSelect: () => { setInspiration(true); setModal(null); } },
  { id: 'manual',      label: '学习手册',   kind: 'overlay', isActive: () => modal === 'manual', onSelect: () => setModal('manual') },
  { id: 'works',       label: '我的作品',   kind: 'overlay', isActive: () => modal === 'works',  onSelect: openWorks },
  { id: 'firstlesson', label: '纸上第一课', kind: 'overlay', isActive: () => modal === 'apprentice', onSelect: () => openApprentice(apprentice.next ?? 'tour-interface'), disabled: !hydrated },
  { id: 'tour',        label: '使用引导',   kind: 'overlay', isActive: () => tourOpen, onSelect: startTour, disabled: !hydrated, tour: true },
];

const activeId = navItems.find(i => i.isActive())?.id;
```

渲染：

```tsx
<nav className="main-nav" aria-label="主导航">
  {navItems.map(item => {
    const active = item.id === activeId;
    return (
      <button key={item.id}
        className={active ? 'nav-active' : undefined}
        aria-current={item.kind === 'page' && active ? 'page' : undefined}
        aria-pressed={item.kind === 'overlay' ? active : undefined}
        data-tour-entry={item.tour || undefined}
        disabled={item.disabled}
        onClick={item.onSelect}>
        {item.label}
        {active && item.kind === 'page' && <span className="nav-dot"/>}
      </button>
    );
  })}
</nav>
```

### 3.3 样式配套

`.nav-dot` 目前是绝对定位的小圆点（`@media(max-width:750px)` 里有 `bottom:11px` 的单独调参），需要确认：

- `.main-nav button` 需 `position: relative`（若 `.nav-dot` 用 `position:absolute`），否则圆点会跑到 `nav` 上；
- **激活态不能只靠颜色**：`nav-active` 已有红色文字 + 圆点，需补一条非颜色线索（圆点即是），满足"不依赖颜色传达状态"；
- 弹层型项打开时的高亮建议用**底色**（`--zs-brand-soft`）而非文字变红，与页面型项区分层级；
- 焦点态沿用全局 `:focus-visible`（`styles.css:7`）。

### 3.4 验收

| 操作 | 期望 |
|---|---|
| 首次进入 | 实验工坊 = `nav-active` + `aria-current="page"` + 圆点 |
| 点击剪纸灵感库 | 灵感库 = `nav-active`；**实验工坊立刻失去** `nav-active` 与圆点 |
| 打开我的作品 | 我的作品临时高亮；实验工坊**保持** `aria-current="page"`（页面没变） |
| 关闭弹窗 | 弹层高亮消失，回到页面型激活态 |
| 键盘 Tab | 六项均可聚焦，激活项有 `aria-current`，读屏可播报"当前页" |

## 4. 移动端头部瘦身（P1）

### 4.1 现状

390×844 实测：`.site-header` 高 **232px**，占 **27%** 的视口高度。三行堆叠：

| 行 | 高度 |
|---|---|
| `.brand`（品牌） | 62 |
| `.main-nav`（6 项，折成 2 行） | 89 |
| `.audio-toggles` | 40 |

无横向溢出（`scrollWidth === clientWidth === 390`）✓，但首屏内容被压掉近三分之三屏。

### 4.2 改法（二选一，推荐 A）

**A. 主导航收进抽屉（推荐）**

- ≤750px 时 `.main-nav` 只显示「实验工坊 / 剪纸灵感库」两个高频项 + 一个「更多」按钮；
- 「更多」展开浮层，放其余 4 项（学习手册 / 我的作品 / 纸上第一课 / 使用引导）；
- 头部降到品牌行 + 单行导航 ≈ **110px**。

**B. 保持 6 项、压缩高度**

- `.brand` 与 `.main-nav` 合并为同一行（品牌缩为纯图标 `brand-mark`）；
- `audio-toggles` 40px 移到页面底部工具条或折叠进设置浮层；
- 头部 ≈ **112px**，改动小于 A，但 390px 宽度下 6 项必然两行，仍偏挤。

**A 与 B 的共同前提**：`audio-toggles` 不该常驻头部——它与主题切换（见 `02-主题系统设计规格.md`）应该合并成同一个「设置」入口，头部只留一个按钮。这一条同时解决了 V4 新增主题切换器的落位问题，建议一并处理。

### 4.3 验收

- 390×844 下 `.site-header` ≤ 120px；
- 六项导航全部可达（抽屉内或折叠内），无横向溢出；
- 触控目标 ≥44×44px（现有 `button` 已有 `min-height:44px` 的宽屏规则，移动端需复核）。

## 5. 视频本地化（P2，与音频改造同批做）

现状：10 段 B 站教程全部 iframe 嵌入，`public/` 下 0 个本地视频。本次走查中 **iframe 未发出任何外部请求**（受限网络），站点正确降级为"原创观察步骤 + 来源链接"，但**离线时没有任何可播放内容**。

改法（与 `03-音频系统设计规格.md` 的音频素材策略一致：先能播、再谈好看）：

1. 保留 iframe 作为**在线首选**（有弹幕、清晰度自适应）；
2. 对每类目至少 **1 段**做本地化：下载 → `ffmpeg` 压缩到 720p / ≤8MB → 放 `public/video/`；
3. 播放器加 `<video controls preload="metadata" poster="...">`，**CSP 需补 `media-src 'self' blob:`**（`scripts/serve.mjs` 当前为 `media-src 'self' blob:`，已含，需复核 `public/video/` 路径可访问）；
4. 在线时优先 iframe，加载失败/超时（`setTimeout` 3s + `onError`）自动切本地 `<video>`；
5. 素材来源与许可记录写入 `docs/content-sources.md`（用户已确认不设授权限制，但仍需留痕）。
