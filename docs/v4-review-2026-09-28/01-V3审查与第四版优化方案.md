## 二、整体评估

**第三版已经把"功能完整"这条线走完了，第四版要解决的是"产品质感"这条线。** 用户反馈的 5 个问题全部属于同一类：功能都在，但细节没有打磨到"让人愿意长期使用"的程度。它们的共同特点是——**根因唯一且可精确定位**，因此修复成本可控、收益立竿见影。

本轮方法：读新模块源码（ApprenticeTasks/AudioToggle/InspirationLibrary/RealCutVideo/audio/sfx/videos.ts/classroom 课程数据），在生产构建上复现用户描述的现象，用运行时数据量化根因（列高/内容高、导航 className、Web Audio 增益链路、CSS 色值统计、控制台与网络请求），并复跑单测。

边界：代理走查，非真人试用；本轮仅 Chromium；未真机触控；B 站 iframe 在本次环境下未加载成功（无外网），因此"视频播放"本身未验证，只验证了降级路径。

## 三、五项反馈的根因与方案

### 1️⃣ 电脑端首页底部大片留白（P0）

> **⚠️ 本节已于同日复测修正。** 初测把元凶记为"右栏视频卡太高"，复测推翻了这个判断：右栏自身也留白 476px，**真正驱动整行高度的是左栏**。以下是修正后的数据与结论；以 `04-布局与导航修复规格.md` 第 1 节为准。

**实测数据（1600×900，`dist v0.3.0`，引导弹层关闭后）**：`.workbench-body` 高度 **1694px**，三栏被 Grid 强制拉伸到等高，但各自内容长度差得很远：

|栏|栏高|内容结束位置|**底部空白**|
|---|---|---|---|
|左栏 `.left-rail`|1694|1694|0|
|中栏 `.canvas-workspace`|1694|1003|**690px**|
|右栏 `.right-rail`|1694|1218|476px|

**根因**：CSS Grid 默认 `align-items: stretch`（实测 `alignItems: "normal"`、`gridTemplateRows: 1693.72px`），三栏被拉到**最高栏**的高度。而最高栏是**左栏 1694px**：

|左栏子项|高度|
|---|---|
|`.apprentice-tasks`（V3 新增·七任务新手面板）|**564**|
|`.mode-switch`|50|
|`.lessons-section`（实验章节）|**543**|
|折叠方式 / 剪切工具 / `.rail-help`|161 + 247 + 51|

两项就占左栏 65%。中栏自身内容（工具栏 62＋双画布 753＋历史 188）只有 1003px，多出的 **690px 就成了空白色块**；右栏内容 1218px，同样留白 476px。

**结论修正**：这不是"某一栏太高"，而是**"三栏内容量差异大 + 强制等高"的结构问题**。右栏视频卡（364px）可以顺手瘦身，但**只改右栏不会解决留白**——左栏不瘦下来，中栏的洞就一直存在。

**V4 方案（见 04 文档第 2 节）：**
1. **左栏瘦身（主工程量，削 ≈740px）**：`.apprentice-tasks` 首次仍展开、点过第 1 个任务后自动收起，折叠态保留进度摘要；`.lessons-section` 桌面端改默认收起或限高滚动（`max-height:300px; overflow-y:auto`）；
2. **中栏弹性填充**：在双画布与历史之间插入可伸缩的 `.workspace-filler` 纸纹过渡带（`flex:1 1 auto; aria-hidden`），把余量吸收到**有设计的位置**，而不是堆成底部死白；**不要简单回退 `styles.css:606`**，回退只会把空白从底部挪到画布与历史之间；
3. **右栏收敛**：视频卡默认折叠为一条 56px 摘要行，点击原位展开；
4. **硬约束**：**保留 `align-items: stretch`**，禁止改 `align-items:start`——三栏背景色各不相同，不等高会让底边参差、分隔线截断，比留白更难看。

**验收**：1280×900、1440×900、1600×900、1920×1080 四个宽度下，任一栏底部**连续空白 ≤160px**，且无横向溢出。脚本骨架见 `04` §2 末尾。

### 2️⃣ 顶部导航不反映当前页面（P0）

**实测**：`App.tsx` 第 473 行把 `className="nav-active"` **写死**在"实验工坊"按钮上，其余五个导航项没有任何激活态。
- 点"剪纸灵感库"→ `main[hidden]=true`、`.inspiration-library` 已渲染，但导航仍显示"实验工坊"高亮、"剪纸灵感库"无标记；
- 打开"我的作品"弹窗（标题"我的纸上实验"）→ 导航同样毫无变化。

**根因**：导航没有单一"当前视图"状态源，激活态是硬编码。项目里已有 `inspiration` 布尔态，只需升级为统一的 `view` 状态。

**V4 方案（04 文档第 2 节）**：引入 `view: 'workshop' | 'inspiration' | 'manual' | 'works' | 'apprentice' | 'tour'` 单一状态；导航激活态由 `view` 派生；modal 型入口在弹窗打开时激活、关闭后回到工坊；同步 `aria-current="page"`；视觉沿用现有 `nav-active` 朱砂下划线＋小圆点（不新增配色）。**六个入口全部有明确激活态，无一个例外。**

### 3️⃣ 音乐声音太小、只有一首、不能选（P0）

**实测复算链路增益**：

|环节|数值|
|---|---|
|音乐总线 `bus.gain`|`10^(-25/20)` = **0.0562**|
|旋律单音 level|0.35 → 实际峰值 **0.0197 = −34.1 dBFS**|
|低音支声|0.15 → **0.0084 = −41.5 dBFS**|
|对比：落剪音效|0.16 = **−15.9 dBFS**|

**根因**：音乐比音效低约 18–20 dB，相当于在正常音量下把手机音量再拉低一半——用户"电脑拉满也听不见"完全属实。另外音乐是**代码生成的单条 16 音五声音阶乐句**（每 1350ms 一个音），`public/` 下没有任何音频文件，因此也不存在"多首可选"。

**V4 方案（03 文档）**：
1. **换成真实曲目**：3–5 首本地音频文件（`public/audio/`），统一**响度归一化到 −16 LUFS**（流媒体标准），默认音量 0.6，峰值不再低于 −6 dBFS；
2. **播放器 UI**：播放/暂停、上一首/下一首、曲目列表（曲名＋时长）、音量滑块、循环模式；偏好持久化；
3. **保留合成乐器句作为"素纸微光"备选曲**（零素材、零体积），列在列表最后，不再作为唯一选项；
4. **音效独立音量**（与音乐分开），默认保持当前 −15.9 dBFS 手感；
5. 素材按用户授权从公开素材站获取（耳聆网／淘声网／FreePD／Freesound／Musopen），转码 128–192 kbps、单曲 ≤4MB，逐条登记 `docs/content-sources.md`；
6. 不动既有行为：仍在用户手势后启动、仍默认关、`visibilitychange` 暂停、失败静默。

### 4️⃣ 主题／背景色切换（P0，本轮最大工程量）

**实测现状**：**完全没有主题系统**。`:root` 只有 10 个 CSS 变量，而 `styles.css` + `media.css` 中散布着 **281 处硬编码色值、256 个不同颜色**（远超一个可维护色板的量级）。

**这正是用户最担心的风险来源**：如果直接在现有代码上叠一层"换背景色"，必然出现对比度崩塌、色彩数量失控、品牌色漂移、交互态（hover/active/disabled/focus）与背景打架。

**V4 方案（02 文档，两步走）**：

- **第一步·色板收敛（必须先做）**：把 256 个色值归并到约 **34 个语义 token**（背景层 4、文字层 4、边框 3、品牌 4、辅助语义 5、交互态 6、画布专用 6、阴影 3，允许每主题微调数值而不新增语义）。这是纯机械但必须做的工作，也是主题能安全切换的前提。
- **第二步·五套主题**（默认第一套）：

|#|主题名|气质|类型|
|---|---|---|---|
|1|素纸（默认）|当前米白暖纸|浅色|
|2|竹青|冷调宣纸／青灰，配靛青辅助|浅色|
|3|朱漆|暖深红棕纸，节庆浓烈|浅色偏深|
|4|玄墨|墨黑纸面、朱砂剪纸、米白文字|**深色**|
|5|靛夜|深夜靛蓝纸面、月白剪纸|**深色**|

- **对比度守卫（自动化）**：新增 `npm run check:contrast`，对 5 主题 × 全部 token 组合计算 WCAG 对比度并输出表格，硬性阈值：正文 ≥4.5:1、大字 ≥3:1、焦点环与边框等非文本元件 ≥3:1；任一不达标即构建失败。**用户担心的"对比度问题、色彩数量失控、品牌与层级问题、交互状态配色问题"由此变成可自动检查的规则，而不是靠肉眼。**
- **圆形涟漪切换动效**：用 View Transitions API（`document.startViewTransition` + `clip-path: circle()` 从点击点扩散），降级为自绘覆盖圆动画；时长 420–600ms，主题在涟漪覆盖屏幕的瞬间切换（避免闪烁）；`prefers-reduced-motion` 下直接切换无动效。
- **切换入口**：顶栏一枚"纸色"按钮 → 弹出小面板（5 个圆形色卡＋名称＋"跟随系统"），不占导航宽度。
- **隔离原则**：导出 SVG／打印页**不跟随主题**（必须固定为白底黑线＋红纸，保证实剪可用）；画布里的几何真值颜色随主题调整（深色主题下红纸提亮、留白提示改用月白）。

## 六、边界与未验证

- 未真机触控；仅 Chromium；未做屏幕阅读器全程；未测低端机性能；
- B 站视频真实播放未验证（本机无外网）；音频"听感"由增益链路数学推导＋用户复现，未经声压计实测；
- 主题切换的视觉观感需在实现后由用户人工审美确认；对比度只保证数值达标，不保证"好看"。

**下一开发对话请先从"色板收敛"和"留白修复"动手（前者是主题的前置，后者用户感知最快）。未实施和验收前，不得把本文建议写成已修复事实。**
