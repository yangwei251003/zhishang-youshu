## 1. 一句话结论

| 项 | 裁决 | 理由 |
|---|---|---|
| P2-1 学习进度总览 | ✅ **做**（0.5–0.75 人日） | 数据**已经全在**，只是没有汇总视图；这是全站"教育价值"最硬的证据 |
| P2-2 作品分享卡 PNG | ✅ **做**（0.5 人日） | **复用已有 `projectSvg()`**，成本极低，传播价值高 |
| P2-3 看图还原挑战 | ⚠️ **只做最小关卡**（1–1.5 人日），做通再扩 | 教学价值最高，但"评分公平性"是真实风险，必须先立住一关 |
| P2-4 教师打印包 | ⏸ **延后**（不排入本轮） | 只在"课堂分发"场景有价值，与当前用户的实际使用路径弱相关 |

**而且这四项都不该排在 V4 主线之前。** 用户已明确"不是为了比赛而开发"——那么真正的优先级判据是"用户自己每天会不会用到"。按这个判据：主题（02）、音频（03）、布局与导航（04）是**用户已经明确说难受**的，必须先做完；P2-1 / P2-2 是做完主线后**半天就能落地的性价比项**；P2-3 是可选增量；P2-4 是场景外延。

## 2. P2-1｜学习进度总览 ✅ 做

### 2.1 为什么便宜：数据已经在手，一行都不用改 schema

| 需要的数据 | 现状 |
|---|---|
| 每课的预测与完成时间 | `ProjectDocument.progress: { lessonId, prediction, completedAt? }[]`（`src/types.ts:12` 附近）✅ |
| 每次尝试的完整事件流 | `ProjectDocument.events`，含 `attempt_start` / `prediction_submitted` / `lesson_complete` / `transfer_complete` / `hint_opened`，`decodeLearningEvent()` 已可解码（`src/io/learning.ts:54`）✅ |
| 全部作品 | `listProjects(): Promise<ProjectDocument[]>`（`src/io/storage.ts:99`）**返回完整文档**，不只是摘要 ✅ |
| 已有导出能力 | `buildLearningRecords(project)` / `downloadLearningRecords(project)`（`src/io/files.ts:209`）✅ |
| 已有列表 UI | 「我的作品」弹窗 `modal === 'works'` 已在读 `archive`，渲染 `.works-list` 与每项 `{foldMode} 层 · {paperSizeMm} mm · {cursor} 道剪口`（`src/App.tsx:553`）✅ |

**结论：这是一个纯粹的"聚合 + 展示"任务，不动几何、不动存储、不动校验。**

### 2.2 要新增什么

1. **聚合函数**（新建 `src/io/progress-overview.ts`，纯函数、可单测）：

   ```ts
   export interface ProgressOverview {
     lessonsTotal: number;            // LESSONS.filter(l => !l.transfer).length
     lessonsCompleted: number;        // 跨全部作品去重：同一 lessonId 只要有一次 completedAt 即算通过
     predictionsTotal: number;
     predictionsMatched: number;      // prediction === lesson.expectedPrediction
     transferCompleted: number;       // 含 hintOpened: false 的"无辅助完成"数
     transferWithHint: number;
     totalCuts: number;               // 全部作品 cursor 之和
     firstAt: string | null;          // 最早 events[0].at
     lastAt: string | null;
   }
   export function buildProgressOverview(projects: ProjectDocument[]): ProgressOverview
   ```

2. **展示位置**：扩展现有「我的作品」弹窗（`modal === 'works'`），在其上插入一段「学习进度」区，而不是新开一个弹窗——**减少一个导航入口，导航栏本来就有 6 项了**。

3. **展示内容**（四行以内，不要做成仪表盘）：
   - `屏幕实验：7 课已完成 4 课`（配 `LESSONS` 长度）
   - `预测与结构相符：3 / 5`
   - `迁移练习：2 题独立完成 · 1 题用了提示`
   - `一共落下 37 刀 · 从 9 月 27 日到今天`

4. **一个"导出学习记录"按钮**：调已有的 `downloadLearningRecords()`。V3 已实现该能力却**没有入口暴露给用户**，这里顺手补上。

### 2.3 为什么值得做（不只是"好看"）

这是全站**唯一能把"学会了吗"变成数字的地方**。这个项目的核心主张是"先预测再观察"的学习设计，但用户看完站只会感觉"挺好用"——评审更会问"你怎么证明有效"。一份"预测与结构相符 3/5、迁移题 2 题独立完成"的汇总，是把教学设计**变成可陈述的证据**，成本半天。这一项性价比明显高于另外三项。

### 2.4 验收

- [ ] 聚合函数有单测（空作品集、同一课多作品重复完成、无 `completedAt`、只有 `prediction` 无完成）；
- [ ] 「我的作品」弹窗顶部显示进度区，数据随关闭弹窗后再打开刷新；
- [ ] 作品数为 0 时不显示进度区（或显示"还没有记录"），不出现 `NaN` / `0/0`；
- [ ] 「导出学习记录」按钮可用，导出内容与 `buildLearningRecords` 一致。

### 2.5 风险

低。唯一注意：`progress` 是**随作品文档走**的，用户删掉某个作品会连带丢那一课的完成记录。所以聚合口径要写清是"当前本机留存的记录"，UI 文案加一句"记录随作品一起保存在本机"。

## 3. P2-2｜作品分享卡 PNG ✅ 做

### 3.1 为什么便宜：矢量图早就能生成了

`src/io/files.ts:145` 已有：

```ts
export function projectSvg(project: ProjectDocument, analysis: Analysis): string
```

它已经把展开后的成品渲染成**纯 SVG 图形**（`regionPath()` 输出的 `<path>`，非 canvas、非截图），`downloadSvg()` 也已在用。所以分享卡只需三步：

1. 取 `projectSvg()` 的结果，外面套一层带边距、标题、统计、站点标识的 SVG 底板（纯字符串拼接）；
2. 用 `new Image()` + `data:image/svg+xml;charset=utf-8,` + `canvas.drawImage` + `canvas.toBlob('image/png')` 栅格化；
3. `URL.createObjectURL` + `<a download>` 下载。

**无需新依赖、无需 html2canvas、无需改变任何几何代码。**

### 3.2 要新增什么

- `src/io/share-card.ts`：`buildShareCardSvg(project, analysis, opts): string` + `exportShareCardPng(project, analysis): Promise<void>`；
- 入口：作品「导出」弹窗（`modal === 'export'`）里加一项「保存分享图（PNG）」，或成品画布下方加一个分享按钮；
- 卡片内容（1290×1290 或 1080×1350）：
  - 主体：成品展开图（复用 `projectSvg`）
  - 角标：`{foldMode} 层折叠 · {cursor} 刀 · 纸 {paperSizeMm}mm`
  - 底部一行：`纸上有数 · 让几何在指尖发生`
  - **不要二维码**（无二维码库，且本机离线场景二维码没意义）

### 3.3 两个必须注意的技术点

1. **字体**：SVG 栅格化时用的字体必须已加载，否则 `canvas.drawImage` 会回退到系统默认字体、中文可能变成方框。做法：`await document.fonts.ready` 之后再栅格化；或分享卡底板文字**只用已在用的 `--serif` 字体栈**（Noto Serif SC / Source Han Serif SC / SimSun），并显式 `font-family` 写死在 SVG 里。
2. **`canvas` 被污染（tainted）**：只要 SVG 内**不引用任何外部图片**（`href="http://..."`），`toBlob` 就不会抛 `SecurityError`。`projectSvg()` 目前是纯 `<path>`，满足条件——但**务必不要在分享卡里加外链 logo 图**，否则 `toBlob` 直接失败。

### 3.4 验收

- [ ] 导出 PNG 尺寸与文字清晰（至少 1080px 宽），下载文件名含作品标题与日期；
- [ ] 无外链图片，`toBlob` 不抛错；
- [ ] 中文字体正确（非方框）；
- [ ] 三种折法（2/4/8）各生成一张，成品图形与屏幕一致；
- [ ] 分享卡上的统计与作品实际数值一致。

### 3.5 风险

低。唯一失败模式是字体未就绪导致的方框，用 `document.fonts.ready` 兜住即可。

## 4. P2-3｜看图还原挑战 ⚠️ 只做最小关卡

### 4.1 为什么它最有教学价值

其它练习都是"我给你一个目标（保留/剪去），你自由发挥"；看图还原是**逆向问题**——"给你成品图案，倒推要剪哪里"。这正是剪纸学习里最难的一步，也是本网站"结构理解"主张的最高阶验证。

### 4.2 为什么不能一次做完：评分公平性是真实风险

要判"还原得像不像"，需要几何比对。已有 `pathsRegions()` 与 `clipper2-ts` 的 `xor` / `intersect`，技术上可行：

```
IoU = area(intersect(用户结果, 目标图案)) / area(union(...))
```

但风险在**难度与宽容度设计**：

- 阈值太严 → 用户画出视觉上几乎一样的结果却判不过，**挫败感极强**；
- 阈值太松 → 随便剪两下就过，练习失去意义；
- 对称图案下，"差一刀"和"多一刀"的 IoU 差距可能很小，**反馈说不清"你差在哪"**；
- 自由创作允许多片纸（`status === 'separated'` 是合法的），而还原题必须是单一连通图案，**规则冲突**。

### 4.3 最小可做版（MVP）边界

**只做这一层，做通再谈扩展：**

| 项 | MVP 范围 |
|---|---|
| 折叠方式 | 固定 4 层（最典型的窗花折法，网格对齐无退化风险） |
| 刀数 | 目标图案由**恰好 1 刀**剪成 |
| 关卡数 | **1 关**（例如"四折·单刀方孔团花"） |
| 判定 | `IoU ≥ 0.92` 判过；`0.75–0.92` 给"很接近了，检查某个角"；`<0.75` 给"再看目标图案的对称" |
| 反馈 | 叠图对比（用户结果半透明叠在目标上，**差异区高亮**）——复用现有 `.inline-comparison` 的对比布局 |
| 不做的 | 难度阶梯、多刀、8 层、计时、排行、关卡编辑器 |

判定逻辑：

```ts
export function scoreReproduction(user: Region[], target: Region[]): number {
  const u = pathsRegions(union(...)) // 用现有 kernel 能力把两侧都规约成 Paths64
  const inter = area(intersect([uPaths], [tPaths], FillRule.NonZero));
  const uni   = area(union([...uPaths, ...tPaths], FillRule.NonZero));
  return uni === 0 ? 0 : inter / uni;
}
```

> ⚠️ 注意：以上签名是**示意**，`clipper2-ts` 的 `area/intersect/union` 入参是 `Paths64`，必须先经 `toGrid()` 转到 0.01mm 整数网格（与 `kernel.ts` 一致），**不能直接传浮点 `Region`**。codex 落地时请照 `engine.ts` 的既有写法来。

### 4.4 验收

- [ ] 1 个关卡可进入、可完成、可重来；
- [ ] 判定函数有单测：完全正确 = 1.0；少剪一角、多剪一刀、完全无关三种情况分别落在预期区间；
- [ ] 叠图对比能看出差异区；
- [ ] 不通过时给的是**可执行的下一步**（"检查左上角"），不是"再试试"；
- [ ] 该模式与"自由创作"互不干扰（进入挑战不改动用户已有作品，用独立项目文档）。

### 4.5 裁决

**做 MVP，但排在 P2-1 / P2-2 之后。** 如果主线（主题/音频/布局）耗时超预期，**这一项可以整体延到赛后**——它不影响任何已有功能，延后没有技术债。

## 5. P2-4｜教师打印包 ⏸ 延后

### 5.1 现状

`src/io/files.ts` 已有单份打印能力：`printHtml(project, analysis)`、`openPrint()`、`downloadPrintHtml()`。教师包要做的是**批量**：把 7 课的模板一次性生成一份可打印的 HTML 合集。

### 5.2 为什么不排入本轮

| 维度 | 判断 |
|---|---|
| 成本 | ~1 人日（批量渲染 + 分页样式 + 每页抬头） |
| 谁会用到 | 只在"老师带一个班"的场景 |
| 用户的实际路径 | 用户是学生、自用；用户三轮反馈（V3/V4）中**从未提到课堂场景** |
| 与比赛的关系 | 用户已明确"不是为了比赛" |
| 复用性 | 依赖于"先有稳定的打印样式"，而打印样式本轮还要被主题系统（02）隔离检查，**顺序上本就不该现在做** |

**裁决：延后，不删。** 等主题系统落地、打印隔离验证通过（`02-主题系统设计规格.md` 的隔离原则要求打印输出永不被主题影响）之后，再评估。

### 5.3 如果以后要做，正确的最小形态

不要做"可配置的教师包"，做**一个按钮**：`导出全部 7 课模板（打印用）`。生成一份 HTML：每课一页，页首是课名 + 目标图案（用 `projectSvg`）+ 一行操作提示，页脚是"纸上有数"。不做班级抬头、不做难度档、不做自定义尺寸——这些是 Mary's Template Maker（见 `v3-review-2026-09-27/03-竞品对标分析.md:24`）的差异化点，但**那是它的产品定位，不是这个项目的**。

## 6. 顺带裁决：六折（FoldMode 6）不做

用户这次只问了 P2，但 `v3-implementation/README.md:88` 把"六折及 P2"并列声明为未纳入，所以一并给结论：**不做，且 V3 的决定是对的。**

这不是"加一个枚举值"，而是**几何内核的改动**，证据在 `src/geometry/engine.ts`：

```ts
// 第 12–20 行：镜像变换表是写死的 2/4/8 二面体群
function reflectPaths(paths: Paths64, mode: FoldMode): Paths64 {
  const variants = [(p) => p, (p) => ({ x: -p.x, y: p.y })];
  if (mode >= 4) variants.push((p) => ({ x: p.x, y: -p.y }), (p) => ({ x: -p.x, y: -p.y }));
  if (mode === 8) variants.push(/* 4 个对角交换 */);
}

// 第 5–9 行：折叠轮廓只处理 2/4/8
export function getFoldedOutline(size: number, mode: FoldMode): Point[] { ... }

// 第 39 行：校验直接白名单
if (![2, 4, 8].includes(project.foldMode)) return '只支持 2、4、8 层折法。';
```

**三个具体障碍：**

1. **变换群完全不同**。2/4/8 是**轴对齐镜像 + 对角交换**，所有坐标仍是整数或简单的符号翻转；六折需要 **60° 旋转**（D6 群），`cos60° = 0.5`、`sin60° = √3/2` 是**无理数**。
2. **整数网格会退化**。整个内核建立在 **0.01mm 整数网格** 上（`SCALE` / `toGrid` / `fromGrid`）。60° 旋转后坐标必须四舍五入回网格，必然产生**几乎重合的顶点与近自相交多边形**——而 `cutIssue()` 明确拒绝这种输入（`simplePolygon()` 检查），`hasUncertainTopology` 会把它标成"退化接触"（现有文案："存在点接触或很细的边界，先检查局部，再用实物验证"）。**六折会让这条降级路径变成常态。**
3. **要连带改的地方很多**：`getFoldedOutline`（30° 楔形轮廓）、`expandCut`（裁剪域）、`reflectPaths`（旋转群 + 方向归一）、`unfold`、`documentIssue` 白名单、`FOLD_NAMES`、折叠示意 SVG、以及**全部 2/4/8 相关的测试假设**。

**估算：2–4 人日，且需重做退化检测，正确性风险高。** 换来的只是"多一个折法"，而现有 2/4/8 已覆盖从对折到八角团花的主流剪纸路径。

**若确实想做**，唯一可接受的路径是**把六折做成独立模块**（独立的旋转对称内核 + 更细的网格精度），而不是往 `FoldMode` 里塞一个 6。成本会失控，不建议。
