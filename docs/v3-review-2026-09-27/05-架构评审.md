# 纸上有数｜架构评审

日期：2026-09-27。对象：v0.2.0 全部源码（src 约 2470 行）与工程配置。本轮为只读评审，未修改代码。

## 1. 总体判断

**架构与项目规模匹配，没有过度设计，也没有失控腐化。** React+TS+Vite 单页、clipper2-ts 唯一几何内核（Worker 隔离）、毫米坐标统一真值、严格 JSON schema 校验、CSP 收紧、无后端——这些决策全部正确且互相自洽。V3 不需要任何架构级重构，只需要按规格增加 3 个小模块（ApprenticeTasks、audio、RealCutVideo）和 1 个可选几何扩展（六折）。

## 2. 分层评审

### 2.1 几何内核（src/geometry）——优

- engine/kernel/client/worker 四层职责清晰；clipper2-ts 整数网格（0.01mm）避免浮点拓扑问题；`expandCut → reflectPaths → unfold → pathsRegions` 管线纯函数化，可独立测试。
- 修复候选 `getRepairs` 的约束设计正确：全序列重算＋目标重检＋重做保护＋按实际面积变化排序取 3 个。**这不是黑箱，是本项目最有技术含量的部分。**
- 已知边界处理诚实：`uncertain-topology` 保守提示、点接触不算可进入、`no-material` 拒绝重复剪切。
- 隐患：修复计算复杂度随刀数增长（每个候选一次完整 analyzeProject），课程最多约 10 刀可控，100 刀自由作品会慢 → V3 D1 超时降级已在规格中。六折扩展时 `reflectPaths` 目前是纯镜像族，六折三角的真实变换含 60° 旋转，须按真实折纸变换群重写该分支并配全套新单测——**这是 V3 唯一有算法风险的改动，做不好宁可不上**。
- `kernel.ts` 未逐行评审的函数（`accessibleRemoval`、`hasUncertainTopology`）已被 71 项单测覆盖关键样例；V3 新增折法时必须为这些函数补六折样例。

### 2.2 状态与 UI（src/App.tsx、components）——良，需控制膨胀

- App.tsx 540 行集中了页面状态机；学习阶段门槛（revealed/hintOpened）、引导副本、修复对照、导出全部一个状态源——在当前规模是优点不是缺点。
- V3 预警：任务栏＋视频＋音频会让 App.tsx 向 800 行逼近。**规格已要求新功能全部进独立组件**（ApprenticeTasks/RealCutVideo/AudioToggle），App 只接线；若 V3 后还要继续加，届时再考虑提取 learnFlow 状态钩子，本轮不做预防性拆分。
- OnboardingTour 的事件守卫（click/pointerdown/focusin/Tab）实现专业，但定位逻辑是单一策略（右侧优先、左退）→ P1-11 的实证缺陷；规格给出四象限避让。
- 组件粒度合理：Dialog/GoalMarkers/PaperCanvas/WorkshopOrnaments 都小而专。

### 2.3 IO 与存储（src/io）——优

- `parseProject` 是教科书级的导入校验：白名单字段、原型链污染键拒绝、深度限制、多边形自相交/重复顶点/面积校验、双精度＋0.01mm 网格双重验证。非法输入不可能污染几何。
- V2 事件编码（value 内嵌 eventVersion:2 JSON）是在不改 schemaVersion=1 前提下的务实兼容，代价是事件语义依赖 codec——V3 新增 apprentice 事件时必须同步 codec 与单测，不得绕过。
- localStorage 单点依赖是已知风险（D3 已列防备）；**不建议**为此上 IndexedDB——对"提示导出备份"就够的场景属于过度工程。

### 2.4 构建与交付（vite.config、serve.mjs、scripts）——良，一处实测缺陷

- CSP 严格（default-src 'self'、object-src 'none'）是参赛加分项，但 `font-src 'self'` 与 vite 字体内联冲突 → **P0-11 实测 6 条控制台错误**。一行修复。
- 脚本矩阵完整：samples/pdf/license/verify:production/package:local/record-demo，参赛材料可复现。
- 端口治理（5187 旧/5188 测/5189 V2）清晰；V3 顺延 5190。
- 包体健康：首屏约 1MB（实测 24 资源），字体子集化按需加载；新增音视频预算：视频 ≤5MB×N、音乐 ≤3MB×2、音效合成优先——全部懒加载，不进首屏。

### 2.5 测试体系——优

- 71 单测＋32 双浏览器 E2E＋生产验证脚本，且 V2 有"早期失败用例保留原始报告不掩盖"的诚实记录文化。V3 验收沿用同一标准：不删断言换通过、新增功能配新测试、失败保留现场。

### 2.6 安全与合规——优

- 无外部请求、无注入面（SVG 自生成、escapeXml、不渲染用户 HTML）、打印弹窗 `opener=null`、CSP 收紧。
- 合规链完整：ai-use-log / human-decisions / THIRD_PARTY_NOTICES / prior-art。V3 新增音视频素材的授权登记直接进现有链条。

## 3. V3 架构决策记录（建议）

|决策|选择|理由|
|---|---|---|
|新手引导|自研扩展，不引库|授权干净、复用 V2 机制、体量 5KB 的 driver.js 也是多余依赖|
|音效|Web Audio 合成优先|零版权、零体积、可程序化|
|音乐|本地授权文件＋默认关|自动播放政策＋评委礼仪|
|视频|本地文件＋preload=none|断网可用、首屏无负担|
|六折|P1 可选，变换群重写＋全套测试|唯一算法风险项，时间不足整体砍|
|状态管理|不引 Redux/Zustand|540 行单状态源仍可控；新功能组件化即可|
|存储|不加 IndexedDB|提示备份已够，避免过度工程|

## 4. 技术债清单（不阻塞 V3，登记备查）

1. App.tsx 行数随 V3 增长，V4 前评估提取 learnFlow hook；
2. serve.mjs 的 CSP 与构建产物的内联策略缺少自动化对账 → verify:production 增加 console 错误断言后闭环；
3. platform.spec.ts 依赖 dev 服务 /src 路径，与生产验证路径分离，新人易混淆 → 在 docs/test-report.md 写清两条路径；
4. 六折若上，`FoldMode` 联合类型从 `2|4|8` 变 `2|4|6|8` 涉及打印模板、GoalMarkers、新建 UI 多处，须一次性改齐（规格 3.4 已列）。

## 5. 结论

V2 架构可以承载 V3 全部规划，无需重构。V3 的工程质量红线只有四条：**CSP 修复后控制台 0 错误；新增模块组件化不进 App.tsx 堆叠；六折要么完整要么不做；全部既有测试一条不许删。**
